# Desktop integration

Use the installed Omarchy CLI and its templates as the source of truth. On the setup used for this project, user themes live under `~/.config/omarchy/themes/` and Omarchy stages the active theme under `~/.local/state/omarchy/current/theme/`. Verify both paths on the target machine. Keep durable changes in user files. Apply them with `omarchy theme set <name>` and verify Hyprland with `hyprctl configerrors`.

- **Window borders and shell widgets.** Keep active and inactive borders distinct. Reuse Omarchy's shell border component and active border spec for custom widgets that should match the window border. A pill without keyboard focus can use hover as its active state when that matches the design. Check the idle and hovered states. Where wallpaper shows through an intended opaque surface, inspect both the app's transparency setting and the compositor's opacity rule.
- **Palette and font sync.** Reuse Omarchy's generated terminal and editor themes. Read the existing user hooks before adding a sync path. When theme or font sync is requested, update only the affected settings, preserve unrelated keys, and make repeated runs safe. Verify a second run does not change files and confirm an actual theme change triggers the hook. Check pointer assets separately from text fonts and the Cursor editor.
- **App-specific theme state.** A settings file can name the right theme while the running app uses a separate palette. Cursor IDE and Cursor Agents are separate surfaces even when they share an executable. Check the IDE's preferred theme as well as its active theme. Verify the Agents app separately. Reuse existing integration code for Codex, T3 Code, Herdr, Zen, GTK, and qBittorrent when present. For Cloudroom, follow the [native palette and GTK workflow](../SKILL.md#cloudroom-theme-integration). Use app-provided settings or import paths where available and inspect the installed version before touching version-specific config.
- **Reload and verification.** Prefer a live reload. If a restart is needed and authorized, close the app gracefully and reopen it from the normal launcher. Verify the active palette and restore window placement if the restart moved it. Do not infer coverage of an entire app from a generated file or an unrelated screen.
